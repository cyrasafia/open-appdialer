# Open App Dialer 技术规格（Spec v2.9）

> 实现以本文为准；与 `scope.md` 冲突时先改文档再改代码。日期：2026-11-14。

## 1. 概述

内置 T9 九宫格键盘的 Android 应用搜索启动器：打开即搜，输入几位数字，一键启动。无联系人、无 widget、无网络权限。

**成功标准**：常用应用 3 次按键内启动；全程不唤起系统输入法；冷启动半秒内可用。

## 2. 术语

| 术语 | 定义 |
|---|---|
| T9 | 九宫格输入：2 兼含 1（ABC）、3=DEF、4=GHI、5=JKL、6=MNO、7=PQRS、8=TUV、9 兼含 0 与 WXYZ；每键候选 = 字母 + 数字本身 |
| 全拼 | 应用名中文逐字展开为完整拼音（微信 → weixin → 934946） |
| 首字母（简拼） | 每字取拼音首字母（微信 → wx → 99） |
| 混合输入 | 逐音节自由组合全拼/简拼（qidq / qdongq） |
| 多音字 | 有多个读音的汉字（重 → chong/zhong），所有读音均可匹配 |
| 匹配序列 | 应用名预计算出的候选数字串集合，匹配 = 查询是某序列的前缀或子串 |
| 冻结应用 | 被 Android 系统休眠（cached app freezer）的后台应用 |

## 3. 用户流程

```
启动 App → 浮窗面板（无遮罩）
  → 空态：新安装应用优先，其余按最近使用时间降序
  → 按数字键（ACTION_DOWN 即上屏）
  → 结果实时过滤（分页：每页 3 项、最多 2 页、横划切换）
      ├─ 点击结果 → 记录使用 → 启动应用 → finish() 并关闭浮窗
      ├─ 无结果 → 提示 + 清空按钮
      └─ 左上键短按清空全部输入；长按进设置
  → 系统返回键 / 点击浮窗外 → 直接关闭浮窗（不清空输入）
```

## 4. 功能规格

### F1 应用数据层

- **数据源**：`PackageManager.queryIntentActivities(MainActivityIntent)`，即**当前用户 profile** 的所有可启动应用；不跨 work profile / 私密空间聚合（Q6 已定）。
- **权限**：manifest 用 `<queries>` 元素声明 `<intent>` MAIN/LAUNCHER 可见性——仅可见带桌面入口的应用（与数据源精确对齐），**不使用** `QUERY_ALL_PACKAGES`（免 Play 专项审核），安装时授予、无运行时弹窗。`INTERNET` 永不申请。
- **应用条目字段**：包名、label、预计算匹配序列、首次安装时间（`firstInstallTime`）、启动次数、最近启动时间。
- **监听**：`PACKAGE_ADDED / REMOVED / REPLACED / CHANGED` 广播 + resume 时 diff 兜底（防漏广播），增量更新列表与缓存。
- **缓存**（`filesDir/apps.json`）：
  - 存包名、label、预计算拼音/匹配序列、使用数据；损坏即静默重建。
  - 目的：冷启动不做拼音解析，直接加载。
  - 首次构建在后台线程，期间界面显示系统进度提示（列表按需渲染）。
- **图标**：内存 LRU；磁盘缓存为 backlog。首屏先渲染文字，图标异步补齐。
- **使用数据**：每次启动 +1 次数、更新时间戳；仅存本地。

### F2 匹配引擎（纯 Kotlin，无 Android 依赖）

**序列生成**（安装/更新时对每个 label 预计算一次）：

1. label 归一化：小写；连续分隔符（空格/标点）折叠。
2. 汉字 → 拼音（含全部读音，多音字不消歧，全部保留）；英文字母原样。
3. 生成候选序列：**全拼序列**（所有音节全拼）、**首字母序列**、以及**分隔符两种处理**（并入特殊字符桶 / 直接删除）。
4. 映射到键位符号：字母 → 所属键（2=ABC … 8=TUV）；数字 2-9 → 自身键位；数字 1 → 键 2 桶；数字 0 与特殊字符（emoji、日文等）→ 键 9 桶。全部字符均可由键盘输入、无死符号（按 3 可命中含数字 3 的应用名；`1DM+` → 序列 `2369`；`12306` → 序列 `22396`）。

**匹配规则**：查询 Q（数字串）命中应用 A，当且仅当存在 A 的某数字串 S 满足：

| 层级 | 规则 | 例（微信 weixin=934946） |
|---|---|---|
| L1 | Q 是全拼序列的前缀或全文 | 9 / 934 / 934946 |
| L2 | Q 是首字母序列的前缀或全文 | 99 |
| L3 | Q 是混合序列的前缀（逐音节状态机匹配，不枚举 2ⁿ 组合） | T9启动器：qdongq → 736647 |
| L4 | Q 是任意序列的子串（任意位置） | Chrome：766（rom） |

**排序**（确定性，同输入同输出）：

1. 层级 L1 > L2 > L3 > L4（越小越前）
2. 前缀/全文 > 子串；匹配位置靠前优先
3. 完整匹配（Q == S）置顶
4. 使用次数多者优先；同次数最近使用优先
5. label 字典序（稳定兜底）

**混合输入语义**：对每个音节允许"完整拼音或仅首字母"两种消费方式，Q 需能从头到尾连续消费（前缀类）或从中间某音节开始消费（子串类）。

**多音字**：任一读音命中即命中（重命名工具 → chongming=2466464 与 zhongming=9466464 均可搜到）。

**拼音数据**：TinyPinyin（Apache-2.0，约 100KB，体积达标的关键依赖）。注意：其原 Maven 坐标发布在已关停的 jcenter，**M2 时以源码 vendoring 方式引入**（附带许可声明）；若多音字覆盖不足，补充自建词表。

### F3 T9 键盘（唯一输入方式）

布局 3×3（无第四行）：

```
[ ⌫/⚙ ] [ 2 ABC 1 ] [ 3 DEF ]
[ 4 GHI ] [ 5 JKL ] [ 6 MNO ]
[ 7 PQRS ] [ 8 TUV ] [ 9 0 WXYZ ]
```

- 左上键（拨号盘 1 位）：短按**清空全部输入**（无退格键；T9 查询通常 2-5 位，清空重打成本低），长按进入设置
- 数字联想：每键候选 = 字母 + 数字本身（键 3 = D/E/F/3；数字 1 并入键 2），支持带数字的应用名（12306、360 等）
- `9` 键 = 数字 9 + 数字 0 + 特殊字符桶（搜 `1DM+` 输 `2369`，`+` 计入 9 桶）
- 数字 `1` 并入 `2` 键：含 1 的应用名可完整输入（12306 → 输 `22396`，前缀命中）
- **数字在 `ACTION_DOWN` 上屏**，不依赖抬起 → 手指滑出按键再抬起也不丢字符（核心需求）；按下即触觉反馈（tick）
- 键高 ≥ 60dp、触控目标 ≥ 48dp，按键主标数字、副标字母
- 无任何入口唤起系统输入法（无 `EditText`，自定义输入展示）
- 清空输入：左上键短按（主路径）、无结果空态的清空按钮；系统返回键不再承担清空

### F4 结果分页与启动

- 结果区为横向分页（HorizontalPager）：**每页 3 项、最多 2 页**（最多展示 6 个联想结果），左右滑动切换，底部 2 个圆点页标
- 空输入排序：**新安装应用优先**（`firstInstallTime` 距今 ≤ 2 小时，服务"刚装好-来找"场景，组内按安装时间降序）＞ **其余按最近使用时间降序**（从未使用排最后，按 label 字典序稳定兜底），取前 6 个
- 输入变化（含退格）后：结果重新过滤并**回到第 1 页**
- 页内条目：图标 + label（单行省略，不换行），横排 3 列
- 匹配数超过 6 个：不额外提示（v2.1 移除"还有 N 个"页脚），继续输入自然缩小
- 无结果：显示"无匹配应用" + 清空按钮
- 点击条目：记录使用 → 启动主 Activity intent → `finish()`
- **长按条目弹出菜单**（v2.7）：
  - 添加桌面快捷方式：`ShortcutManager.requestPinShortcut`（图标取自内存缓存、shortLabel 为应用名、intent 为目标应用启动 intent）；仅 API 26+ 且启动器支持时显示（旧版广播方案需额外权限，不采用，保持零权限）
  - 查看详情：跳转系统应用详情页并关闭浮窗
  - 卸载：`ACTION_DELETE` 系统卸载确认并关闭浮窗；列表经 `PACKAGE_REMOVED` 广播 / resume diff 自动更新
- 启动失败（`ActivityNotFoundException` / `SecurityException` / 冻结导致的异常）：toast 提示，并尝试跳转系统应用详情页兜底；**验收：Android 15/16 真机上冻结应用可从本应用直接启动**

**候选布局（v2.0 真机反馈）**：页内 3 个候选**横排**（图标上、名称下），不回显输入数字；结果区高度各状态恒定（浮窗高度不变）。名称用紧凑字体（labelSmall）单行省略，候选项与按键均无背景色，按压有涟漪 + 缩放动画（v2.4）；图标 60dp 与系统启动器相当、间距收紧给名称让宽（v2.5）；点击候选后冻结列表，防止使用数据更新导致点击项跳位（v2.5）；候选屏蔽应用自身（v2.5）。

**键面（v2.0）**：共键数字并排展示——2 键主标 `1 2`（副标 ABC）、9 键主标 `9 0`（副标 WXYZ）。

**键面视觉（v2.4）**：所有键无背景色，按压有涟漪 + 缩放动画；左上键与其他键同款上下布局（上为清空图标、下为设置图标）。

**清空语义（v2.4）**：点击清空后候选区显示**空白**，不恢复默认列表（减少误解）；再次输入数字恢复搜索。

**窗口位置（v2.0）**：浮窗底部对齐（gravity BOTTOM），下缘距屏幕底约 16dp（略高于 dock/手势条）；浮层宽度上限 480dp（v2.4）。

### F5 主题

- 深色 / 浅色 / 跟随系统，设置页三选一，存 DataStore
- Android 12+ 默认 Material You 动态取色，低版本/不支持时用预置色板（主色靛蓝）
- 深浅两套完整 Material 3 配色；对比度满足 WCAG AA

### F6 设置与关于

- 单一设置页，仅两项：主题（F5）、关于（版本号、GPL-3.0、仓库地址）
- 入口：长按键盘左上键（⌫/⚙）

### F7 国际化

- 默认英文 `values/`，中文 `values-zh-rCN/`，全量覆盖无硬编码文案
- 搜索明确支持中文、英文；其他文字（日文假名等）并入键 9 特殊字符桶，精确匹配为 backlog

### F8 窗口形态（浮窗）

- 主界面为浮窗样式：dialog 主题的 Activity，浮层面板，不占满全屏、**无遮罩**（v2.3：MIUI 打开动画的边缘缩放会与遮罩叠加穿帮，且遮罩为黑底来源）
- 系统返回键（含返回手势）或点击浮窗外区域：**直接关闭浮窗，不清空输入**
- 浮窗宽度贴屏留边距，横竖屏与分屏可用；视觉细节实现时定
- 不需要 `SYSTEM_ALERT_WINDOW` 权限（跨应用悬浮唤起仍属 backlog）
- 禁用 starting window 预览，且 `windowIsTranslucent` 跳过 Android 12+ 系统 SplashScreen（消除启动黑底的根因），v31 覆盖将 splash 背景亦置透明（v2.1/v2.2）
- `excludeFromRecents`：关闭后不出现在后台窗口列表（v2.1）
- 启动/关闭动画置空（`windowAnimationStyle` 覆盖 taskOpen 等，spec v2.5）：消除 MIUI 启动缩放动画导致的桌面变暗约 1s（小米官方文档建议方案）
- **遗留已接受**（v2.6）：从桌面图标启动仍有约一帧轻微闪烁——MIUI 桌面自绘的图标点击动效，早于应用窗口创建，主题层无法禁用（已试尽 preview/splash/translucent/动画置空/壁纸垫底，壁纸垫底在 MIUI 反而垫出应用图标白底）；彻底解法是通知/快捷开关唤起 overlay（backlog，用户暂不接受）

## 6. 技术设计

### 6.1 选型

- Kotlin + Jetpack Compose（Material 3）（Q1 已定），单 `:app` module，无 DI 框架（手动构造），`StateFlow` 单向数据流
- 体积账：Compose 基线 ~1.5MB，上限 2MB（CI 检查）
- R8/Minify + Baseline Profiles（Compose 库自带 ProfileInstaller），压冷启动差距
- 高刷：不调用 `setFrameRate` 锁帧，跟随系统刷新率（触摸交互自动升频）
- Gradle Kotlin DSL + version catalog

### 6.2 结构

```
app/src/main/java/com/cyrasafia/openappdialer/
├── data/        AppRepository / AppEntry / AppsCache / UsageStore / PackageEventReceiver
├── search/      PinyinParser / SequenceGenerator / T9Matcher / Ranking   ← 纯 JVM，可独立单测
├── ui/
│   ├── theme/   Color / Theme
│   ├── search/  SearchScreen / SearchViewModel / Keypad / ResultPager
│   └── settings/SettingsScreen
└── MainActivity.kt
```

### 6.3 数据模型（要点）

```kotlin
data class AppEntry(
  val packageName: String,
  val label: String,
  val sequences: List<DigitSequence>, // 全拼/首字母/分隔符两态，type + digits + syllableBoundaries
  val launchCount: Int,
  val lastLaunchAt: Long,
)
```

### 6.4 构建/发布

- CI（GitHub Actions）：PR 跑 `test`；tag `v*` 构建 release APK（本地 keystore 签名，密钥不进仓库）并发布 GitHub Release
- 版本：`v0.1.0` 起步（首个可用），semver
- F-Droid 提交为 backlog（需可复现构建）

## 10. 变更记录

- 2026-11-15 v2.10 根因定论（官方文档互证）：启动闪烁 = 启动转场素材缺失的系统兜底——Google《Splash screens》要求 splash 背景为不透明单色（透明属未定义行为，各版本/OEM 兜底色不同：深色→黑、HyperOS 4 浅色→白）；AOSP《Task snapshots》：桌面打开动画以 TaskSnapshotSurface/splash 为素材，半透明任务两者皆无效，SurfaceFlinger 以纯色填充。结构性矛盾，应用侧不可修，彻底解法仍是通知唤起（backlog）
- 2026-11-15 v2.9 HyperOS 4.0（Android 17）浅色模式启动白屏：判定为 v2.6 同族问题（系统桌面启动转场对透明窗口快照按主题色合成，深色→黑、浅色→白），主题层无剩余手段，接受遗留；模拟器复现受阻（google_apis android-37.0 r08 镜像不稳定：uiautomator/package 服务/intent 解析均异常），未做无验证的盲目改动；彻底解法仍为 backlog 的通知/快捷开关唤起
